# Voice-based university information assistant
 
A voice assistant that answers spoken questions about the master's programmes in AI, Computer Science and Technology at the University of Gothenburg. You press Start, ask something like "What are the entry requirements for Computer Science?", and it answers out loud using text it collected from the university's own pages.
 
It was built for a dialogue systems course in about a week, so it is a working prototype and not a finished product. The limitations at the bottom are real and worth reading before you rely on an answer.
 
## What it does
 
- Finds the eight programmes listed under "AI, Computer Science and Technology" on the university's master's programmes page.
- Collects each programme's syllabus (a PDF for some, an HTML page for others) and the text of the programme web page, which has tuition, application periods and entry requirements.
- Cuts that text into chunks, turns each chunk into a vector, and stores them in Qdrant.
- For each question, looks up the closest chunks and gives them to a language model, which writes a short answer using only that text.
- Listens and speaks through SpeechState (Azure speech recognition and synthesis).
- Uses an XState state machine to control the conversation, including silence, errors, a Stop button, and a follow-up question when the user does not say which programme they mean.
The programmes are Computer Science, Digital Leadership, Game Design and Technology, Human-centered Artificial Intelligence, Information Technology and Learning, Language Technology, Logic, and Software and AI Engineering.
 
## How it works
 
There are two parts. The first runs once to collect and index the data. The second runs for every question.
 
```
Built once
  scraper (Python)  ->  data/ files  ->  ingest (Node)  ->  Qdrant
 
For every question
  microphone -> Azure speech recognition -> XState machine
     -> Qdrant search -> llama3.1 -> Azure speech synthesis -> speaker
```
 
Embeddings and the language model run on Ollama (`qwen3-embedding` with 384 dimensions, and `llama3.1`). Qdrant runs in Docker.

## Requirements
 
- Node.js 18 or newer (developed on 24)
- Python 3.9 or newer
- Docker Desktop (on Windows, with WSL integration turned on)
- Ollama with `qwen3-embedding` and `llama3.1` pulled, either installed locally or reached through an SSH tunnel to a course server
- An Azure Speech resource (key and region)
- Chrome or Edge, with microphone access
## First-time setup
 
```bash
git clone https://github.com/Aveiro11/Voice-Based-University-Information-Assistant.git uni-assistant
cd uni-assistant
 
# python side
python3 -m venv .venv
source .venv/bin/activate
pip install -r scraper/requirements.txt
 
# node side
npm install
```
 
Create `src/azure.ts` with your own key. The file is in `.gitignore`, so it stays on your machine:
 
```ts
export const KEY = "your-azure-speech-key";
```
 
The region is set to `northeurope` in `src/dm.ts`. If your resource is somewhere else, change `azureRegion` and the token `endpoint` there.
 
Collect the data and build the index:
 
```bash
python scraper/scrape_programmes.py
docker compose up -d
npm run ingest
```
 
`ingest` needs Ollama to be reachable (see below) and takes a minute or two. It deletes and rebuilds the `programmes` collection each time, so running it again is safe.
 
## Running it
 
Start Docker Desktop first, then:
 
```bash
cd ~/projects/my_project/uni-assistant
docker compose up -d
 
# only if Ollama runs on a course server: open the tunnel
ssh -f -N -o ServerAliveInterval=30 -L 11434:127.0.0.1:11434 mltgpu
 
curl -s http://localhost:6333/collections          # should list "programmes"
curl -s http://localhost:11434/api/tags | head -c 150   # should print {"models":[...
 
npm run dev
```
 
Open http://localhost:5173 in Chrome or Edge, press Ctrl+Shift+R, click Start and allow the microphone. Headphones help, because otherwise the microphone can pick up the assistant's own voice.
 
If the collections list is empty after a restart, run `npm run ingest` again. The collection has disappeared after restarts on the development machine more than once.
 
Useful checks that do not need the browser:
 
```bash
npm run search -- "What are the entry requirements for Computer Science?"
npm run ask -- "How much is the tuition for Game Design and Technology?"
```
 
`search` prints the retrieved chunks with their scores. `ask` runs the whole text pipeline and prints the answer.
 
## Data collection
 
`scraper/scrape_programmes.py` opens the master's programmes listing page, finds the "AI, Computer Science and Technology" section, and visits each programme page. On each one it looks for a link labelled Syllabus. That link points to a PDF on some programmes and to an HTML page under `/syllabus/` on others. When the intakes link to different syllabi, the one under the latest intake is used, and the reason is written to `metadata.json`.
 
The programme page text is always saved as well. It holds tuition, application periods and entry requirements that the syllabus does not have. If no syllabus can be read, the programme is still kept with the page text only.
 
The first version of the scraper read only three of the eight programmes, all PDFs. It missed the others because it only looked for PDF links and because one text container it picked was empty. Both were fixed.
 
You can scrape a single programme with `python scraper/scrape_programmes.py n2cos`.
 
## Retrieval and answering
 
Chunking happens in `scripts/ingest.ts`. PDF text is cut at numbered headings and at "Semester N", HTML text at its headings. A section under 1200 characters stays whole. A longer one is split with overlap, and its heading is repeated at the top of each piece. Page footers and page counters are removed first. An earlier version split every 500 characters and produced a chunk that contained only "3/4" and another that separated "Semester 2" from its list of courses.
 
Each chunk is embedded together with the programme name, and is stored with the programme code and name, the source type (syllabus, programme page or overview), the page number for PDFs, and the source URL. One extra chunk lists all the programmes.
 
`retrieve()` in `src/rag.ts` returns the six closest chunks. If the question names a programme (or a known nickname such as "game design"), the search is limited to that programme.
 
`generateAnswer()` sends `llama3.1` a prompt with the list of programmes, the labelled excerpts, and a set of rules: answer in one to three short spoken sentences, use only the excerpts, name the programme, say that fees and dates may have changed, and say so when the excerpts do not contain the answer. The temperature is 0.2. If nothing was retrieved, it returns a fixed message and does not call the model.
 
## Dialogue manager
 
The state machine is in `src/dm.ts`.
 
| State | What happens |
|---|---|
| Prepare | SpeechState loads its speech recognition and synthesis |
| WaitToStart | Waits for the Start button, because browsers need a click before playing audio |
| Greeting | Says hello and names the field |
| Listening | Opens the microphone |
| NoInput | After about 6 seconds of silence: "Do you have any other questions?", then a second, softer reminder |
| Goodbye | After a third silence, says goodbye and returns to WaitToStart |
| Processing | Checks the question. Empty goes back to Listening |
| Clarify | The question needs a programme and none is known: asks which one, keeps the question, and listens |
| Retrieving | Queries Qdrant |
| GeneratingAnswer | Calls the language model |
| Speaking | Speaks the answer, then listens again |
 
If retrieval or generation fails, the assistant says so out loud and goes back to Listening. A connection error gets its own message. The Stop button leaves any active state and returns to WaitToStart. Pressing it when the assistant is already stopped does nothing.
 
Clarify is triggered by keywords (entry, tuition, course, semester, deadline and similar) in a question that names no programme. The last programme the user mentioned is remembered, so "and the tuition?" after a Computer Science question does not ask again. Pressing Start clears that memory.
 
## Configuration
 
| What | Where |
|---|---|
| Chat model | `CHAT_MODEL` in `src/rag.ts` |
| Embedding model and size | `embed()` and `VECTOR_SIZE` in `src/clients.ts` |
| Number of chunks per question | `limit` in `retrieve()` in `src/rag.ts` |
| Programme nicknames | `ALIASES` in `src/rag.ts` |
| Words that trigger Clarify | `PROGRAMME_TOPICS` in `src/rag.ts` |
| Silence timeout, voice, language | `settings` in `src/dm.ts` |
| Spoken messages | the constants at the top of `src/dm.ts` |
| Category to scrape | `CATEGORY` in `scraper/scrape_programmes.py` |
 
## Test results
 
These are from the text pipeline (`npm run ask`) after the multi-programme version was built.
 
| Question | Result |
|---|---|
| Which programmes are there in AI, computer science and technology? | Named all eight |
| What are the entry requirements for Computer Science? | Correct: a 180-credit bachelor's, credits in mathematics, programming and data structures, and English |
| How much is the tuition for Game Design and Technology? | Gave the fee and first payment from the programme page, with a note that fees may have changed |
| Which courses are mandatory in the second semester of Language Technology? | The four semester 2 courses |
| What are the entry requirements? (no programme named) | Wrong: answered for Information Technology and Learning. This is what the Clarify state was added for |
| Is there a master's programme in cooking? | Said there is no mention of one and suggested other programmes |
 
By voice, the speech recogniser heard "corpses" instead of "courses" in one test and retrieval still returned the right chunks.
 
## Known limitations
 
- Speech recognition makes mistakes, and course codes such as LT2216 are recognised poorly.
- Fees and application dates come from the programme web page on the day it was scraped. Run the scraper again to refresh them.
- A small local model can answer when it should say it does not know. The prompt asks for honesty but there is no guarantee. Retrieval scores cannot be used as a cut-off, because answerable and unanswerable questions got similar scores.
- Clarify only triggers on the keyword list. Other vague questions can still be guessed.
- The assistant covers programme-level information only, not individual course syllabi.
- The language model runs behind an SSH tunnel on the development setup. When the tunnel drops, the assistant can only apologise.
- The Qdrant collection has been empty after some restarts, so the index may need rebuilding.
## Troubleshooting
 
| Symptom | Likely cause | Fix |
|---|---|---|
| `docker` not found or cannot connect | Docker Desktop is not running or WSL integration is off | Start Docker Desktop and wait for "Engine running" |
| `ECONNREFUSED 6333` | Qdrant is not running | `docker compose up -d` |
| `ECONNREFUSED 11434` or "I can't reach my language model" | The Ollama tunnel is down | `pkill -f "11434:127.0.0.1"` and open it again |
| `Collection ... doesn't exist` | Qdrant started empty | `npm run ingest` |
| Start button stays on "..." | Wrong Azure key or region | Check `src/azure.ts` and the browser console |
| The assistant answers by itself in a loop | The microphone hears the speakers | Use headphones |
| Typing in the debug box does nothing | The assistant is stopped | Press Start first. Text typed while it is speaking waits until it listens |
